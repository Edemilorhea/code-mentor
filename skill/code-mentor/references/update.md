# 改既有的導讀：更新、重做、加深、看不懂

`guide.json` 已經有內容時讀一次；使用者說加深或看不懂時也讀這一份。

要重寫或新增站時，照 `SKILL.md`「哪一步讀哪一份」先讀 `plan.md`、`station.md`（各一次）。

## 選模式

**`guide.json` 已經有內容時**（`collect` 印出「guide.json 已存在，沿用」）：先選模式。

| 模式 | 使用者說 | 做法 |
|---|---|---|
| 更新（預設） | 「導讀這個分支」「重新產」「更新導讀」「再跑一次」，或其他沒有下面關鍵字的說法 | 沿用 `guide.json`，只處理變動的檔案 |
| 重做 | 「重做導讀」「整份重做」「從頭導讀」「重新規劃」「打掉重寫」 | **不要讀舊檔**，從流程第 3 步重新規劃，直接覆寫 |

- 「重新產」是**更新**，不是重做。
- 加深、改某一站、看不懂，照下方「加深」與「使用者說看不懂時」，不屬於這兩種模式。
- 「重做導讀，另存一份」：`collect` 加 `--new`。

## 更新模式

1. `collect` 會和上次的 `diff.json` 比對（以路徑為準，不看 `fNN`），印出「新增／內容有改／移除／只改格式／只有行號移動」清單。它已經自動把 `guide.json` 裡舊的檔案 id 換成新編號；只有行號移動的檔案，註解行號也已跟著移動。**不要自己再比對，也不要讀整份 `guide.json` 或 `diff.json`。**
2. 依清單處理：
   - 內容有改：只 `show` 這些檔案，重寫引用它們的站（照下方「使用者說看不懂時」的「只改那一站」做法）。
   - 新增：併進資料流上相符的既有站；找不到相符的站，才新增一站。
   - 移除：參照已被改成 `gone:…`，從站的 `hunks`、`notes` 和 `files` 裡拿掉。
   - 只改格式、只有行號移動：不用處理。
3. 不准改其他站的 `id`、標題、順序和文字。
4. 有變動時，同步更新 `features` 和 `evidence`（含比對範圍與 HEAD sha）。`features` 有變動時才做流程第 3.5 步的確認。
5. 照常 `check`（它會指出失效的參照，就是要改的地方）、`build`。回報改了哪幾站、新增了哪幾站。
6. `collect` 印出「變動超過一半」，或主要情境變了（例如多了一個新功能）時，不要自己切換模式，先問：「變動很大，要不要重做導讀？」

## 加深（使用者說「加深成導讀」「加深成教學」「改成概覽」）

1. 不要重跑 `collect`，除非程式在上次之後又改過。直接改現有的 `guide.json`。
2. 把 `depth` 改成新等級，只補 `SKILL.md`「每一級寫什麼」表中這一級多出來的欄位。補之前先讀那些欄位對應的那一份（例如加深成教學要讀 `logic.md`）。已寫好的站和註解不要重寫。
3. 「改成概覽」不刪內容，只改 `depth`，並告訴使用者原有的註解還在。
4. 重新 `check`、`build`，告訴使用者補了什麼。

## 使用者說看不懂時

不要整份重寫。使用者貼回「看不懂：第 N 站「…」 檔名 L行號（摘要）」時，用站號和行號定位：只 `show` 那一段、只讀 `guide.json` 裡那一站。

1. 找出**缺的那座橋**：是少一個名詞定義、少一個步驟，還是順序不對？對照 `station.md`「看得懂」的三個問題，看是哪一題答不出來。
2. 只改那一站或那則註解（必要時加一則 detail）。
3. 一次只加**一個更小的步驟**，用專案裡已出現的詞。
4. 必要時補一個 `intuition`。
5. 重新 `check`、`build`，告訴使用者改了哪一站。
